# 작업 공간 규약

서비스 코드는 프로젝트 루트에, 실행 기록과 역할별 산출물은 `.seed/`에 둔다.
에이전트끼리는 대화가 아니라 **이 파일들로** 주고받는다. 컨텍스트가 압축되거나 세션이 바뀌어도 이 파일들만 있으면 이어서 진행할 수 있어야 한다.

## 폴더 구조

```
.seed/
├── state.json            # 실행 상태 (오케스트레이터만 쓴다)
├── request.md            # 사용자의 처음 요청 원문
├── log.md                # 단계별 진행 기록 (단계마다 1~3줄)
├── decisions.md          # 모든 결정 D-NNN (모두 덧붙임)
├── handoff.md            # 외부 서비스 교체 · 배포 시 할 일 (모두 덧붙임)
├── toolbox-raw.md        # 이 세션에서 쓸 수 있는 스킬 · 에이전트 목록 (오케스트레이터)
├── toolbox.md            # 설치된 플러그인 활용 배치 · 게이트 · close 실행 목록 (도구 정찰)
├── rules/                # 이 파일과 autonomy.md 사본
├── product/
│   ├── prd.md            # 제품 요구사항
│   ├── done.md           # 완성 기준 DoD-NN 체크리스트
│   └── backlog.md        # 백로그 B-NNN
├── architecture/
│   └── architecture.md   # 스택 · 구조 · 데이터 모델 · API · 실행 명령
├── design/
│   ├── design-system.md  # 디자인 시스템 · 토큰
│   └── screens.md        # 화면 명세
├── cycles/NN/            # 사이클 번호 두 자리 (01, 02, ...)
│   ├── plan.md           # 이번 사이클 범위 · 수용 기준 (기획자)
│   ├── build.md          # 구현 기록 (개발자)
│   ├── report.md         # 테스트 · 피드백 보고 (테스터)
│   └── shots/            # 스크린샷 (테스터 · 디자이너)
└── final-report.md       # 완성 보고 (오케스트레이터)
```

## 파일 담당

| 경로 | 쓰는 쪽 |
| --- | --- |
| `state.json`, `request.md`, `log.md`, `final-report.md`, `toolbox-raw.md` | 오케스트레이터 |
| `toolbox.md` | 도구 정찰 에이전트 |
| `product/*`, `cycles/NN/plan.md` | 기획자 (planner) |
| `architecture/*` | 설계자 (architect) |
| `design/*`, 디자인 토큰 소스 파일 | 디자이너 (designer) |
| 애플리케이션 소스 · 단위/통합 테스트 · README · `cycles/NN/build.md` | 개발자 (developer) |
| e2e 테스트 · `cycles/NN/report.md`, `cycles/NN/shots/` | 테스터 (tester) |
| `decisions.md`, `handoff.md` | 모두 (덧붙이기만, 남의 항목 수정 금지) |

다른 역할의 파일을 고쳐야 하면 직접 고치지 말고, 반환 보고의 **요청** 칸에 적는다. 오케스트레이터가 다음 단계에서 담당자에게 전달한다.
디자인 토큰 소스 파일의 위치는 설계자가 `architecture.md`에 정한다.

## ID 규칙

- 결정 `D-001`, 백로그 `B-001`, 완성 기준 `DoD-01`
- 수용 기준 `AC-<사이클>-<번호>` (예: `AC-03-2`)
- 이슈 `I-<사이클>-<번호>` (예: `I-03-5`), 심각도 P0~P3
  - P0: 실행 · 빌드 불가, 데이터 손실, 보안 구멍
  - P1: 핵심 흐름 실패, 수용 기준 미달
  - P2: 부가 기능 오류, 눈에 띄는 UX 문제
  - P3: 사소한 문제

## 반환 형식

모든 역할 에이전트는 작업을 마치면 아래 형식으로만 돌려준다(20줄 이내). 자세한 내용은 파일에 쓰고, 반환에는 요약만 쓴다.

```
## 결과 · <역할> · 사이클 N · <단계>
- 산출물: <쓴 파일 경로들>
- 요약: <무엇을 했는지 1~5줄>
- 결정: <D-NNN 목록 또는 없음>
- 고용: <고용한 하위 에이전트와 맡긴 일, 또는 없음>
- 확인: <실제로 실행해서 확인한 것과 결과>
- 요청: <다른 역할에 넘길 일, 또는 없음>
- 다음 단계에 전달: <다음 단계가 알아야 할 것>
```

테스터는 마지막 줄에 `완성 판정: 가능 | 불가 (근거)`를 덧붙인다.
기획자는 완성 검토를 맡았을 때 마지막 줄에 `완성 승인: 예 | 아니오 (근거)`를 덧붙인다.

## 설치된 도구

모든 역할은 일을 시작할 때 `.seed/toolbox.md`에서 자기 단계 · 역할 행을 확인하고 `autonomy.md` 7장대로 활용한다.
사용자가 설치한 플러그인의 에이전트(`<플러그인>:<에이전트>`)도 고용 대상이다. 쓴 도구는 반환 보고의 **고용** 칸에 함께 적는다(예: `스킬 ui:design`, `에이전트 feature:implementer`).

## 서브에이전트 고용

모든 역할 에이전트는 필요하다고 판단하면 `Agent` 도구로 하위 에이전트를 고용할 수 있다.

- **고용할 때**: 일이 서로 독립적인 둘 이상의 큰 덩어리로 나뉠 때, 또는 따로 전문성이 필요할 때(도메인 조사, 보안 검토, 접근성 검토 등). 작은 일은 직접 한다.
- **인원**: 한 번에 최대 4명.
- **종류**: toolbox.md에 맞는 에이전트가 있으면 그것을 먼저, 없으면 자기 역할 타입(`seed:developer` 등)이나 `general-purpose`. 조사만 할 때는 `Explore`.
- **브리프에 꼭 넣을 것**: 목표, 먼저 읽을 파일(`.seed/rules/autonomy.md`, `.seed/rules/workspace.md` 포함), **맡는 파일 범위(서로 겹치지 않게)**, 완료 기준, 반환 형식.
- **책임**: 하위 결과를 검토하고 통합하는 것은 고용한 에이전트의 몫이다. 하위 결과를 검토 없이 그대로 넘기지 않는다.
- **깊이**: 하위 에이전트도 같은 규칙으로 고용할 수 있다. 깊이 제한(기본: 메인 대화 아래 3단)에 닿으면 `Agent` 도구가 없어지므로 직접 한다.
- 고용 내역은 반환 보고의 **고용** 칸에 적는다.
