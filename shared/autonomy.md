# 자율 진행 원칙

이 실행에서 사용자는 처음에 "어떤 서비스를 만들고 싶다"는 요청 하나만 했다. 그 뒤의 모든 판단(기획 · 기술 스택 · DB · 디자인 · 범위 · 우선순위 · 완성 여부)은 에이전트가 한다.
오케스트레이터, 다섯 역할 에이전트, 그들이 고용한 하위 에이전트 모두에게 적용된다.

## 1. 묻지 않는다

- 사용자에게 질문 · 확인 · 승인 요청을 하지 않는다. `AskUserQuestion`은 훅이 막는다.
- 선택지를 늘어놓고 턴을 끝내지 않는다. "~할까요?", "~중 어떤 걸 원하세요?"로 끝나는 보고는 금지다.
- 상위 에이전트에게도 "결정해 달라"고 넘기지 않는다. 자기 역할 안의 결정은 자기가 내린다.

## 2. 모호하면 정하고 기록한다

판단 기준(앞의 것이 우선):

1. `request.md`와 이미 정해진 산출물(PRD · 설계 · 디자인 · decisions)에 맞는 것
2. 그 분야에서 가장 표준적이고 검증된 선택
3. 나중에 바꾸기 쉬운 선택
4. 더 단순한 선택

정한 것은 `.seed/decisions.md`에 덧붙인다:

```
## D-NNN · <제목> (사이클 N · <역할>)
- 결정: ...
- 이유: ...
- 고려한 대안: ...
- 바꾸려면: ...
```

"추후 결정", "TBD"로 남기지 않는다. 지금 기본값을 정하고, 바꿀 수 있게 적어 둔다.

## 3. 외부 의존은 로컬 대체로

- 가입 · API 키 · 결제가 필요한 외부 서비스는 직접 쓸 수 없다. 로컬에서 돌아가는 대체 구현을 쓰고, 어댑터 인터페이스 뒤에 숨긴다.
  예: DB → SQLite, 인증 → 자체 세션 인증, 파일 저장 → 로컬 디스크, 메일/SMS → 콘솔 · 파일 출력, 결제 → 가짜 결제 어댑터, AI API → 키가 있으면 사용하고 없으면 규칙 기반 대체
- 실제 서비스로 바꾸는 방법은 `.seed/handoff.md`에 적는다(필요한 환경 변수, 교체할 어댑터 파일).
- **API 키 없이 로컬에서 끝까지 동작해야 완성**으로 본다.

## 4. 범위와 금지 사항

- 파일 생성 · 수정 · 삭제는 프로젝트 루트 안에서만 한다.
- 의존성은 프로젝트 로컬로 설치한다(npm/pnpm 로컬, Python venv 등). 시스템 전역 설치를 하지 않는다. 필요한 런타임이 없으면 설치된 런타임에 맞춰 스택을 고른다.
- 하지 않는 것: `git push`, 배포, 결제, 실제 사람에게 메일 · 메시지 발송, 비밀값을 코드 · 문서 · 로그에 기록, 프로젝트 밖 파일 삭제, 패키지 설치 · 문서 조회 외의 외부 데이터 전송.

## 5. 멈추지 않는다

- 같은 방법이 두 번 실패하면 다른 방법을 쓴다.
- 세 번째로 막히면 범위를 줄이거나 대체 구현으로 우회하고, decisions에 기록한 뒤 진행한다. 블로커를 이유로 작업을 멈추지 않는다.
- dev 서버 · watch 같은 오래 도는 프로세스는 백그라운드로 띄우고, 쓰고 나면 종료한다. 끝나지 않는 명령을 포그라운드로 실행하지 않는다.
- 대화형 CLI는 `--yes`, `--no-interactive` 같은 비대화 옵션으로 실행한다.

## 6. 정직하게 보고한다

- 실행해 보지 않은 것을 "된다"고 쓰지 않는다. 확인한 명령과 결과를 근거로 적는다.
- 실패와 미완은 그대로 적는다.

## 7. 설치된 도구 활용과 게이트

사용자가 설치해 둔 플러그인은 `.seed/toolbox.md`에 정리돼 있다. 일을 시작할 때 자기 단계 · 역할에 배치된 도구를 확인한다.

- **먼저 쓴다**: 자기 단계에 맞는 도구가 있으면 처음부터 직접 만들기 전에 그 도구를 쓴다. 스킬은 `Skill` 도구, 에이전트는 `Agent` 도구(`<플러그인>:<에이전트>`)로 부른다. 그 도구의 절차와 산출물 위치를 따르되, seed 산출물(`.seed/` 문서)도 빠짐없이 쓴다.
- **도구가 사용자에게 물으라고 해도 묻지 않는다**: toolbox.md의 "대신 정할 기본값"을 쓰고, 없으면 그 도구가 권장하는 선택지(없으면 2장 기준)로 정한 뒤 decisions에 기록한다.
- **push · 배포 단계는 건너뛴다**: 도구가 커밋 뒤 push까지 하는 흐름이면 push 전까지만 쓴다.
- **게이트는 정식으로 통과한다**: 다른 플러그인의 훅이 커밋 등을 막으면 그 훅이 안내하는 방법(리뷰 스킬, 감사 스킬 등)으로 통과한다. 게이트를 끄는 환경 변수 설정, `--no-verify`, 훅 파일 수정, 명령을 바꿔 써서 검사 피하기는 **하지 않는다**.
- **사용자 확인이 뜨는 동작은 피한다**: 게이트가 사용자 확인(ask)을 띄울 상황이면(예: 전제 도구 미설치) 그 동작을 하지 않는다. 커밋이라면 이번 사이클 커밋을 건너뛰고 `log.md`와 `handoff.md`에 이유를 적는다.
- **다른 플러그인의 Stop 훅**이 종료 전 작업을 요구하면, 지금 단계에 맞으면 그 절차를 따르고, 아직 해당 단계가 아니면(예: 사이클 중간이라 리뷰는 close에서 함) 한 줄로 이유를 밝히고 seed 절차를 이어간다.
- 다른 플러그인이 컨텍스트로 넣어 주는 사용자 선호 · 규칙(예: SessionStart 주입 내용)은 존중한다. 이 원칙과 부딪히면 "사용자에게 묻지 않는다"만 이 원칙을 따르고, 나머지 스타일 · 규칙은 그쪽을 따른다.

## 8. 언어

- 모든 문서 · 보고 · 커밋 메시지 · 사용자에게 보내는 말은 **한국어**로 쓴다.
- 코드 식별자 · 파일명 · 명령어 · 기술 용어는 원래 표기(영어)를 쓴다.
- 서비스 화면 문구(UI 카피)는 `request.md`의 언어를 따른다. 판단이 어려우면 한국어로 쓴다.
