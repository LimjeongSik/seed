# 도구 정찰 가이드

이 세션에 설치 · 활성화된 다른 플러그인(스킬 · 명령 · 에이전트 · 훅)과 프로젝트 · 사용자 설정의 훅을 조사해서 `.seed/toolbox.md`를 만든다.
목적은 두 가지다.

1. **활용**: 사용자가 설치해 둔 도구를 사이클의 알맞은 단계와 역할에서 쓰게 한다. 맞는 도구가 있으면 seed 에이전트가 처음부터 직접 만드는 것보다 그 도구를 먼저 쓴다.
2. **게이트 대응**: 다른 플러그인의 훅이 막거나 확인을 요구하는 동작(커밋 · 푸시 · 종료 등)을 미리 알아 두고, **그 플러그인이 정한 방법으로 통과**하게 한다.

이 작업은 파일을 읽기만 한다. `.seed/toolbox.md` 외에는 아무것도 고치지 않는다.

## 1. 입력

- `.seed/toolbox-raw.md`: 오케스트레이터가 자기 컨텍스트에서 옮겨 적은, 이 세션에서 쓸 수 있는 스킬 · 명령 · 에이전트 타입 목록(이름과 설명). **활성화 여부는 이 목록이 기준이다.** 여기 없는 플러그인은 설치돼 있어도 꺼진 것으로 본다.
- `~/.claude/plugins/installed_plugins.json`: 플러그인별 설치 위치(`installPath`). 같은 플러그인이 여러 개면 `scope`가 `user`인 것, 또는 `projectPath`가 현재 프로젝트인 것을 고른다. 여러 개가 맞으면 `lastUpdated`가 가장 최근인 것. 맞는 것이 없으면(다른 프로젝트에만 설치 기록이 있는 경우 등) 그 플러그인의 가장 최근 `installPath`를 쓴다. 버전 차이만 있을 뿐 구성은 같다고 본다.
- 프로젝트 `.claude/settings.json`, `.claude/settings.local.json`, `~/.claude/settings.json`의 `hooks`와 `env`.

## 2. 플러그인별 조사

목록의 이름 접두사(`review:codex`이면 플러그인 `review`)로 플러그인을 묶는다. `seed` 자신과 Claude Code 내장 스킬은 제외한다. 플러그인마다:

1. `installPath`를 찾는다. 못 찾으면 목록의 설명만으로 판단하고 "설치 위치 미확인"으로 적는다.
2. 스킬 · 명령의 `SKILL.md` / `commands/*.md` 앞부분(frontmatter와 처음 40줄 정도)을 읽는다:
   - 무엇을 하는가, 언제 쓰라고 하는가
   - **사용자에게 묻는 지점**이 있는가(설치 여부 확인, 선택지 제시 등)
   - **push · 배포 · 외부 발송**을 하는가
   - 다른 도구를 전제로 하는가(예: codex CLI). 전제 도구가 설치돼 있는지 `command -v <도구>`로 확인한다
3. 에이전트 `agents/*.md`의 frontmatter(name · description · tools)를 읽는다. 호출 이름은 `<플러그인>:<에이전트>`다.
4. `hooks/hooks.json`과 훅 스크립트 앞부분 주석을 읽는다. 훅마다:
   - 이벤트와 대상(`PreToolUse` + `Bash` → 명령 검사, `Stop` → 종료 검사, `SessionStart` → 컨텍스트 주입 등)
   - **막는 동작**(예: 리뷰를 통과하지 않은 변경의 `git commit`)
   - **통과하는 정식 방법**(예: `review:codex` 스킬 실행)
   - **사용자 확인(ask)을 띄우는 조건**(예: 전제 도구가 없을 때)
   - 켜지는 조건(opt-in 여부 등)과 끄는 환경 변수. 끄는 방법은 기록만 하고 **쓰지 않는다**

## 3. 단계 · 역할 배치

조사한 도구를 사이클 단계와 역할에 배치한다. 예시:

| 도구 성격 | 단계 · 역할 |
| --- | --- |
| 요구사항 · 리서치 · 기획 문서 | plan · 기획자 |
| 프로젝트 규칙 · 린터/포매터 설정 · 스캐폴딩 | design · 설계자, build(사이클 1) · 개발자 |
| UI · 디자인 | design · 디자이너, build · 개발자 |
| 기능 구현 워크플로우 · 구현 에이전트 | build · 개발자 (하위 에이전트로 고용) |
| 리팩터링 | improve · 개발자, 또는 사이클 2+ build |
| 테스트 작성 · 실행 | build · 개발자, verify · 테스터 |
| 코드 리뷰 · 보안 감사 | gate (커밋 전) · 개발자 |
| 진행 문서 · CLAUDE.md 같은 문서 유지 | close · 개발자 |

**쓰지 않는 도구**로 분류하는 기준: push · 배포 · 외부 발송이 핵심인 도구(이 실행은 push하지 않는다), 사용자 개인 설정 · 유지보수용 도구, seed 흐름과 정면으로 겹쳐 둘 다 쓰면 충돌하는 도구. 단, push 전 단계(테스트 · 리뷰 · 감사)를 따로 쓸 수 있으면 그 부분은 활용 도구로 넣는다.

## 4. toolbox.md 형식

```
# 도구함
갱신: <시각> · 사이클 N

## 단계별 활용
| 단계 | 역할 | 도구 | 호출 방법 | 언제 · 어떻게 | 주의 |
(호출 방법: 스킬은 `Skill` 도구에 이름, 에이전트는 `Agent` 도구의 subagent_type)

## 게이트
| 플러그인 | 이벤트 | 막는 동작 | 통과 방법 | 사용자 확인이 뜨는 조건 | 현재 상태 |
(현재 상태: 예 — "codex 설치됨 → 통과 가능", "codex 없음 → 커밋 시 사용자 확인 발생")

## close 단계 실행 목록
커밋 전에 순서대로 실행할 것 (게이트 통과 스킬, 문서 유지 스킬 등). 없으면 "없음".

## 사용자에게 묻는 지점이 있는 도구
| 도구 | 묻는 내용 | 대신 정할 기본값 |

## 쓰지 않는 도구
| 도구 | 이유 |
```

반환은 `workspace.md`의 반환 형식을 따르고, **요약**에 활용 도구 수 · 게이트 수 · close 실행 목록을 적는다.
